## Summary
An architect analysis concluded the project already has agentic architecture (orchestrator + isolated worker patterns) but lacks automation triggers and async digests — the gap between manual orchestration and organically-growing background work is essentially a cron scheduler — and identified mem-bank job scheduling (converting manually-triggered memory consolidation into continuous background work on existing infrastructure) as the smallest honest first step, rather than rebuilding for hypothetical future workflows. A follow-up architecture assessment concluded mem-bank is the project's core differentiator with no mature open-source fit (plain markdown, human-auditable, local-first, memory portable inside groves), so ownership beats adoption; this produced a video critique plus four concrete improvements (tool-failure capture in session summaries, decay metadata for forgetting, graduation-lifecycle tests, unattended scheduling with a morning digest) and eight filed GitHub issues (#5–#12) covering mem-bank, carried-over infrastructure, and observability, while `opencode-claude-memory` was saved to persistent memory as a migration reference. Later orientation work on the mem-bank engine (capture via `small-bank.py` SessionEnd hooks, job queueing, graduation to big-bank) fed a proposed rewrite of `modes/meta/architect/context.md` emphasizing silent-failure observability, idempotency of producers, and event re-firing as structural lessons backed by real incidents. Three further design issues were filed against the mem-bank/trigger system: #16, requiring `bank_capture_prompt`/`this-bank-prompt.md` filtering by default rather than silently allowing unfiltered capture when missing; #18, replacing regex-over-transcript-text triggering with structured `session_crawler`-based path/tool-type matching to cut false positives (paths merely printed) and false negatives (edits to sibling files); and #24/#25, proposing a centralized `.claude/mem-bank/` context template instead of hand-copied per-bank `context.md` files, plus a design choice between the current semantic read pattern and hook-driven injection of small-bank context. This entire thread is also the direct motivation for extracting the mem-bank engine into the standalone `diotima-garden/mneme` repository, executed separately (see [[mneme-extraction-repo-split]]).
